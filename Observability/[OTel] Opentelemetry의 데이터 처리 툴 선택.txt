# Opentelemetry의 데이터 처리 툴 선택

# 목적
	- 오픈텔레메트리 콜렉터에서 보내는 로그를 EndPoint로 보낼 때 데이터를 가공해서 보내야함
		오픈텔레메트리 콜렉터 -> 데이터가공 -> 카프카 -> 아파치 스톰
	- 특정 필드의 데이터만 필요함

# 오픈텔레메트리 로그 규격 및 필요 필드
	- 필요한 데이터는 logRecords 배열에 들어있는 로그 데이터
	- 로그데이터 중에서도 body의 stringValue 와 traceId , spanId
	=====================================================================
	{
	  "resourceLogs": [
		{
		  "resource": {...},
		  "scopeLogs": [
			{
			  "scope": {...},
			  "logRecords": [
				{ 	
					"body": {
						"stringValue": "### LampController start"
						} 
					"traceId" : "ac21153b7a5579fd1a63ef7e0659379b",
					"spanId" : "ac21153b7a5579fd1a63ef7e0659379b"
					},
				{ /* log 2 */ },
				{ /* log 3 */ }
			  ]
			}
		  ]
		}
	  ]
	}
	=====================================================================

# fluent-bit

	- 플루언트 비트의 철학
		=====================================================================
		"로그 파이프라인은 가볍게,트레이스 상관관계는 OpenTelemetry Collector나 Backend에서"
		=====================================================================
		그래서 로그레코드 안의 바디 데이터(로그원문) 만 파싱해서 보내도록 설계 되어있음
	- 로그 데이터만 수집함
	- attribute 데이터 수집 불가
	- traceId , spanId 데이터 수집 불가
	- 경량화
	- 처리 속도 빠름
	- 로그 데이터만 활용한다면 간단하게 사용가능
	- lua 기반
	- 수집된 데이터는 아래와 같이 저장됨
	=====================================================================
	v1_logs: [1769275011.1090294645, {"log":"### LampController start"}]
	v1_logs: [1769275011.1095956545, {"timestamp":"2026-01-25 02:16:51.232","service":"OG077201"}
	=====================================================================



# Dataprepper
	- java기반
	- 수집된 데이터를 Json기반으로 파싱해서 보여줌
	- attribute 데이터 수집 가능
	- 수집한 데이터 변환/추가 가능
	- Opensearch 생태계에 포함되어 있지만 kafka로의 호환성 좋음

# 선택
	- 로그데이터만 사용 할꺼다 -> fluent-bit
	- 데이터 처리와 trace id, span id 가 필요하다 -> dataprepper
